# 测试生成器

补测试的目的是锁住行为,不是凑覆盖率。一条会失败的断言,胜过十条永远绿的。

## 1. 读懂再写

- 读目标实现,列出行为清单:正常路径、边界值、错误路径。
- 看现有测试的组织方式(文件位置、命名、断言风格),新测试保持一致,不引入第二套风格。

## 2. 写最小真实用例

- 每个行为一个用例,名字说清"什么输入 → 什么结果"。
- 优先真实输入,少用 mock;必须 mock 时只 mock 边界(网络、时钟、文件系统)。
{{#if isPython}}
- pytest:同构用例用 parametrize 合并;公共 fixture 放 conftest.py。
{{/if}}

## 3. 跑到绿

{{#if hasTests}}
- 跑 `{{testCommand}}`,全绿才算完;顺手确认新用例没有明显拖慢整个套件。
{{else}}
- 本项目还没配测试命令:先补上测试框架和 test 入口,再回来把用例跑绿。
{{/if}}

## 4. 结束语

- 汇报:覆盖了哪些行为、哪些边界**故意没测**以及为什么——诚实的空白比虚假的全覆盖有用。
